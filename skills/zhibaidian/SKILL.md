# 别生造

把"读者必须先解码这个词，才能继续读"的表达揪出来，改回直接写内容。

文档里的概括性表达只有两种：

- **压缩**：读者只看这个表达，就能预测它覆盖什么，可以自己决定跳过还是细读。标题、加粗句、通行术语、段首标签，正常情况下都是压缩。
- **生造**：读者看不出它指什么，必须停下来猜，或者读完正文再回头对照。

压缩是文档的骨架，生造是理解负担。本 skill 只做一件事：区分这两者，把生造改回内容本身。

和 shuorenhua 的区别：shuorenhua 管"像模板、像表演"（套话、收尾腔、商业黑话、语域漂移）；本 skill 管"正确但费解"。一段文字可以两种问题都有，但两个 skill 各改各的，不互相代劳。

语言：规则与语言无关。中文文档为主，英文文档和中英混排里的 `Resilience Layer`、`adaptive orchestration strategy` 按同样的检验处理。

## When to use

- 用户说"这词啥意思""看不懂""不知所云""太绕""别生造词""别整黑话""说明白点"
- 用户要求审查文档可读性，或检查标题、标签、术语是否准确概括内容
- 用户要按可读性审稿或改写设计文档、技术说明、研究笔记、README、PR 描述、issue
- Agent 自己在写以上文档，交稿前自查

不要硬套：

- 用户要去 AI 味、去套话、去收尾腔 → 用 shuorenhua
- 文本主要是代码、日志、命令、配置、报错
- 用户要的是事实校对或逐字翻译
- 文学、诗歌、有意的修辞写作，或对外文案里的标语

## 执行顺序

按顺序做，不跳步。每一步的检验对象不同，不要用一个检验代替全部：

0. **判目标读者**：从文档类型、所在项目、用户说明判断这篇给谁看、属于哪个领域。后面所有"通行""能预测"都按这个读者判，不按"所有人"。
1. **通读全文，圈出三类对象**：
   - 标签：标题、加粗句、段首标签、列表项冒号前的名字
   - 词：领域术语、本文自造的词、首字母缩写
   - 行文句子
2. **标签**：过「三问检验」，再做「结论对齐」（四类问题第 2 条）。两项都过才放行。
3. **词**：过「三问检验」。其中通行术语要做「代入定义」（第 3 条），同一个东西是否全文只有一个名字也在这一步查。
4. **句子**：做「复述测试」（第 4 条）。
5. 按命中的问题类型执行对应动作。
6. 回读（见「回读检查」）。
7. 输出（见「输出合同」）。

## 三问检验

对每个可疑的标签或词按顺序问，命中即停：

1. **是领域通行术语且按本义使用（把标准定义代入句子，句子仍成立），或本文已给出定义并一致使用的词？** → 放行。通行术语但代入定义后句子不成立 → 不放行，按第 3 类「占用既有词」处理。
2. **不是的话，目标读者只看这个表达，能否预测下文的范围，足够决定跳过还是细读？** → 放行，这是压缩。
3. **两条都不满足** → 生造。删掉，直接写内容本身；缩写则展开。

自造词不是原罪。给了操作定义、全文一致使用的自造词按第 1 条放行。问题只出在一次性、无定义、下文没有任何地方接住的装饰性词组上。

## 四类问题

标注模式的 `问题类型` 字段只用这四个名字。识别信号的形态和类型的对应关系：

| 形态（见 [识别信号](./references/signals.md)） | 问题类型 |
|---|---|
| 比喻式命名、抽象名词堆叠、临时组合词、未展开缩写、同一概念多名 | 1. 生造词与标签 |
| 标签只概括前提 | 2. 标签错位 |
| 借术语当形容词 | 3. 占用既有词 |
| 形容词替代机制、名词短语替代动作 | 4. 抽象词代替机制 |

抽象名词堆叠和临时组合词出现在行文里而不是标签上时，仍按第 1 类处理；第 4 类专指整句信息被抽象词吃掉、复述不出动作的情况。

### 1. 生造词与标签

标题、加粗句、段首标签、列表项的名字，或行文里的一个词，在下文没有对应物。常见形态：比喻式命名（`缓存是系统的稳定器`）、抽象名词堆叠（`韧性恢复流程`、`协调策略`）、临时组合词（`语义锚点`、`上下文对齐层`）、未展开的项目内部缩写（`DSM 负责下发`）、同一个东西在全文换了几个名字（`切片 / 分片 / 数据块` 混用）。

动作：删掉标签词，把正文结论直接写成标签；行文里的词删掉直写；缩写在首次出现处展开；多名合并成一个，用出现最多或已有定义的那个。

### 2. 标签错位

标签只概括了前提、背景或话题，正文的结论却是另一件事。错位比没有标签更糟：读者按标签分配注意力，读完发现对不上，等于被骗着读了一段。三问检验抓不到它：一个完全可预测的标签也可能和结论对不上。

检查（结论对齐）：把正文结论压成一句话，和标签对比。对不上就改标签，不改正文。

### 3. 占用既有词

用已有固定含义的术语表达另一个意思：把"快"写成 `原子的`，把"有缓存"写成 `幂等`，把"不相关"写成 `正交`。占用比生造更糟：生造让读者困惑，占用让读者自信地理解错。

判据（代入定义）：把术语的标准定义代入句子，句子还成立吗？不成立就是占用。

动作：换成想表达的直白说法，或换成真正对应的术语。**上下文不足以确定作者本义时，保留原词并标注待确认**（例如 `"原子"指事务原子性还是速度？待确认`），不默认删掉——删掉一个声称等于改动事实。

### 4. 抽象词代替机制

标题上的生造好认，行文中的靠**复述测试**：读完一句，能否说出"谁、做了什么、结果是什么"？只能复述出一堆抽象词，说明这句的信息被抽象词替代掉了。典型信号是形容词代替机制（`智能的调度`、`优雅的降级`）和名词短语代替动作（`采用乐观并发的协调策略`）。

动作：落回原文或上下文已有的信息。正文其他段、代码、配置里有具体机制就写具体机制；原文本来没有，就把表达压回作者实际声称的范围，或标注缺口。**不能为了"更具体"编造原文没有的机制、数字或步骤。**

## 目标读者的卡顿是证据

目标读者说"这说的是啥"，就是数据。不能论证读者不该卡，也不能替读者判断负担——改写者不是目标读者。

卡在哪，动作不同：

- 卡在生造词、错位标签、抽象句 → 改表达，不是向读者解释这个词"其实是什么意思"。
- 卡在**通行术语**（`背压`、`幂等`）→ 术语保留，不删不换；在首次出现处补一句定义或链接。删掉通行术语会让文档失去精确性，代价高于多一句定义。

## 保留规则

- 领域通行术语保留，不要求用户证明它通行。`幂等`、`背压`、`p95`、`最终一致性`、`HTTP`、`TTL` 在技术文档里直接放行。
- 本文定义过、且一致使用的自造词保留。
- 能预测内容的概括保留，哪怕它抽象。`这个服务读多写少` 是压缩，不是生造。
- 引用原文、命令、接口名、字段名、配置项、报错、代码标识符按字面保留。
- 项目已有的术语表和团队约定优先于本 skill 的默认判断。
- 措辞改动不得改变结论、范围、条件、数字、责任主体。

## 输出合同

默认输出改写结果，不附审稿过程。只在高风险改动处加一行极短说明，例如：`"稳定器"下文无对应物，标签改为正文结论。`

输出形式按载体定：

- **文档是工作区里的文件** → 直接编辑文件。回复里只列改动点：位置、`原文 → 改后`、高风险处一句理由。不把整篇文档贴回对话。
- **短文本贴在对话里**（约 300 字以内）→ 给整段改写版。
- **长文本贴在对话里** → 只给改动的片段，每处 `原文 → 改后`。没列出的部分表示不动。
- **Agent 自查自己的草稿** → 直接改稿交付，不附说明，不汇报改了什么。

### 标注模式

用户说"先别改，先标问题""这段哪里看不懂""只做审稿"时启用（对应 shuorenhua 的 annotation mode）。不给整段改写稿，只列最重要的 1–5 个点，每点四个字段：

- `问题类型`：生造词与标签 / 标签错位 / 占用既有词 / 抽象词代替机制
- `触发点`：命中的词或句子
- `读者会卡在哪`：一句话说明为什么解不出来
- `建议动作`：删掉直写 / 改标签对齐结论 / 换直白说法 / 标注待确认 / 落回已有信息 / 标注缺口 / 补定义 / 保持不动

整段没有命中时，不列条目，只输出一行：`未发现生造词、标签错位、占用或抽象替代，建议保持不动。` 不为了凑数硬找。

## 回读检查

提交前逐项过：

1. 每个标签和正文结论对齐。
2. 行文每句能复述出"谁做了什么"。
3. 改动没有引入新的费解词。用一个自己顺手的抽象词替换原来的抽象词，等于没改。
4. 事实没动：结论、范围、条件、数字、责任主体逐项可追溯。拿不准的占用是标注了，不是删了。
5. 没有补原文没有的机制、数字、步骤；查不到的地方标了缺口，不是编了一个。
6. 通行术语和已定义词没有被误杀。读者卡住的通行术语是补了定义，不是删了词。
7. 缩写首次出现处已展开；同一个东西全文只剩一个名字。
