# 直白点

把"读者必须先解码这个词，才能继续读"的表达揪出来，改回直接写内容。

三种情况都算"必须先解码"：

- **生造**：读者看不出它指什么，必须停下来猜，或者读完正文再回头对照。`韧性恢复流程`、`语义锚点`、`DSM`，以及 agent 给自己刚做的事临时起的名字（`双阶段校验策略`、`exact-head check`）。
- **不必要的术语**：词的意思是准确的，但这句话的读者不需要这个精度，换成直白说法一点信息都不丢。`做了门控` 实际是"先检查条件，不满足就不往下走"；`形成闭环` 实际是"做完并确认了结果"；`输出合同` 实际是"输出规则"。读者认识这个词也要多转一道弯。词指的就是它的本义操作时（对文件算哈希、开事务、加索引）直接用，这不算不必要。
- **没问过的对立项**：`不是 X，而是 Y`、`X，而非 Y`、`重点不在 X，在 Y`。读者没提过 X，作者为了衬托 Y 自己立一个 X 再打倒。读者要先接住 X、否定 X，才到 Y，而 Y 一句话就能说完。

对立面是**压缩**：读者只看这个表达，就能预测它覆盖什么，可以自己决定跳过还是细读。标题、加粗句、段首标签、读者真正需要的术语，正常情况下都是压缩。压缩是文档的骨架，上面三种是理解负担。

和 shuorenhua 的区别：shuorenhua 管"像模板、像表演"（套话、收尾腔、商业黑话、语域漂移）；本 skill 管"正确但费解"。两者在 `闭环`、`落盘`、`兜底` 这类词上有重叠，重叠处本 skill 直接改，不转交。其他问题各改各的。

语言：规则与语言无关。中文为主，英文和中英混排里的 `Resilience Layer`、`gating`、`contract` 按同样的检验处理。

## When to use

只在下面三种情况启用，其余时候不主动应用：

- 用户说"直白点""说明白点""这词啥意思""看不懂""不知所云""太绕""别生造词""别整黑话"
- 用户要求审查文档可读性，或按可读性审稿、改写设计文档、技术说明、研究笔记、README、PR 描述、issue
- 用户点名本 skill（`直白点`、`zhibaidian`、`$zhibaidian`），或 agent 在当前任务里已经引用了它

启用后有两个对象：用户给的文本走「执行顺序」；agent 自己在这次任务里写的回复、说明、注释、提交说明走「Agent 自己输出时」。没启用时，agent 的日常输出不受本 skill 约束。

不要硬套：

- 用户要去 AI 味、去套话、去收尾腔 → 用 shuorenhua
- 文本主要是代码、日志、命令、配置、报错
- 用户要的是事实校对或逐字翻译
- 文学、诗歌、有意的修辞写作，或对外文案里的标语

## Agent 自己输出时

本 skill 启用后，agent 在这次任务里写的所有给人读的内容——回复、解释方案、说明改动、汇报、注释、提交说明——边写边过下面五条，不另起审稿流程，不附说明。用户只贴了一段文本要改写时，改写结果和回复里的说明都算在内。

1. **不用下文接不住的词。** 一个词只有你自己知道指什么、后面也没解释 → 直接写它指的东西。
2. **不给自己刚做的事起名字。** `加了一层双阶段校验`、`做了 exact-head 检查`、`采用 editorial-row 布局`，以及连字符拼出来的复合形容词 → 写做了什么：`先查表头再查内容`。名字是给需要反复指代的东西起的，一次性的做法直接描述。
3. **术语先问必要性。** 每个术语问一句：换成直白说法，这句话丢信息吗？不丢 → 用直白说法。丢 → 保留，紧跟一句解释。判据见「术语必要性」。
4. **不立靶子。** 用户没提过 X 时，`不是 X，而是 Y` 直接写 Y。也不主动列举"我没做 X""X 保持不变"；用户问了范围，或读者读到这里会误以为改了 X，才写。
5. **每句能复述出"谁做了什么"。** 复述不出来的句子重写。

默认读者：没在这个项目里泡过、但有基本常识的人；读者的背景从用户的提问和上下文推断。哪怕对方是工程师，解释方案时也按这个读者写——用户要看的是方案本身。

跟用户走：用户自己先用了某个术语，或项目术语表、代码标识符里有它，就用同一个词，不替换。

## 执行顺序

审稿和改写时按顺序做，不跳步。每一步的检验对象不同，不要用一个检验代替全部：

0. **判目标读者**：从文档类型、所在项目、用户说明判断这篇给谁看、属于哪个领域。后面所有"通行""能预测""需要这个精度"都按这个读者判，不按"所有人"。
1. **通读全文，圈出三类对象**：
   - 标签：标题、加粗句、段首标签、列表项冒号前的名字
   - 词：领域术语、本文自造的词、首字母缩写
   - 行文句子
2. **标签**：过「三问检验」，再做「结论对齐」（六类问题第 2 条）。两项都过才放行。
3. **词**：过「三问检验」。通过第 1 问的术语再过「术语必要性」（第 5 条）；同一个东西是否全文只有一个名字也在这一步查。
4. **句子**：做「复述测试」（第 4 条）；带 `不是…而是…` 一类对比结构的句子再做「靶子检验」（第 6 条）。
5. 按命中的问题类型执行对应动作。
6. 回读（见「回读检查」）。
7. 输出（见「输出规则」）。

## 三问检验

对每个可疑的标签或词按顺序问，命中即停：

1. **是领域通行术语且按本义使用（把标准定义代入句子，句子仍成立），或本文已给出定义并一致使用的词？** → 不是生造。通行术语接着过「术语必要性」；通行术语但代入定义后句子不成立 → 按第 3 类「占用既有词」处理。
2. **不是的话，目标读者只看这个表达，能否知道它指什么？** 标签看能否预测下文范围、足够决定跳过还是细读；行文里的词看能否不停下来就读懂。 → 能就放行，这是压缩。
3. **两条都不满足** → 生造。删掉，直接写内容本身；缩写则展开。

自造词不是原罪。给了定义、全文一致使用的自造词按第 1 条放行。问题只出在一次性、无定义、下文没有任何地方接住的装饰性词组上。

## 术语必要性

对通过三问第 1 问的术语再问一句：**换成直白说法，这句话丢信息吗？**

- **不丢** → 换成直白说法。写这个词在这句话里实际指的动作，不是查一个固定替换词。`门控` 在一处是"先检查权限"，在另一处是"达到阈值才放行"，各写各的。
- **丢** → 保留术语。目标读者不是同行时，首次出现处紧跟一句直白解释；是同行就直接用。
- **不做这项检验的场景**：面向同领域读者的技术文档、API 文档、事故复盘、需要检索和跨文档一致的术语、代码标识符。这些场景术语就是压缩，换掉反而失去精确性。

常见"准确但不必要"的词和它们通常实际指什么，见[识别信号](./references/signals.md)第 9 条。列表只是代表项，判据永远是那一句问话。

## 六类问题

标注模式的 `问题类型` 字段只用这六个名字。识别信号的形态和类型的对应关系：

| 形态（见[识别信号](./references/signals.md)）                             | 问题类型          |
| ------------------------------------------------------------------------ | ----------------- |
| 比喻式命名、抽象名词堆叠、临时组合词、给自己的做法起名、未展开缩写、同一概念多名 | 1. 生造词与标签   |
| 标签只概括前提                                                           | 2. 标签错位       |
| 借术语当形容词                                                           | 3. 占用既有词     |
| 形容词替代机制、名词短语替代动作                                         | 4. 抽象词代替机制 |
| 术语代替白话                                                             | 5. 不必要的术语   |
| 不是 X 而是 Y、主动列举没做什么                                          | 6. 没问过的对立项 |

抽象名词堆叠和临时组合词出现在行文里而不是标签上时，仍按第 1 类处理；第 4 类专指整句信息被抽象词吃掉、复述不出动作的情况；第 5 类专指词本身用对了、只是读者不需要；第 6 类专指句子结构多出一个读者没提过的项。

### 1. 生造词与标签

标题、加粗句、段首标签、列表项的名字，或行文里的一个词，在下文没有对应物。常见形态：比喻式命名（`缓存是系统的稳定器`）、抽象名词堆叠（`韧性恢复流程`、`协调策略`）、临时组合词（`语义锚点`、`上下文对齐层`）、给自己刚做的事起名（`双阶段校验策略`、`exact-head check`、`editorial-row 布局`）、未展开的项目内部缩写（`DSM 负责下发`）、同一个东西在全文换了几个名字（`切片 / 分片 / 数据块` 混用）。

动作：删掉标签词，把正文结论直接写成标签；行文里的词删掉直写；缩写在首次出现处展开；多名合并成一个，用出现最多或已有定义的那个。

### 2. 标签错位

标签只概括了前提、背景或话题，正文的结论却是另一件事。错位比没有标签更糟：读者按标签分配注意力，读完发现对不上，等于被骗着读了一段。三问检验抓不到它：一个完全可预测的标签也可能和结论对不上。

检查（结论对齐）：把正文结论压成一句话，和标签对比。对不上就改标签，不改正文。

### 3. 占用既有词

用已有固定含义的术语表达另一个意思：把"快"写成 `原子的`，把"有缓存"写成 `幂等`，把"不相关"写成 `正交`。占用比生造更糟：生造让读者困惑，占用让读者自信地理解错。

判据（代入定义）：把术语的标准定义代入句子，句子还成立吗？不成立就是占用。

动作：换成想表达的直白说法，或换成真正对应的术语。**上下文不足以确定作者本义时，保留原词并标注待确认**（例如 `"原子"指事务原子性还是速度？待确认`），不默认删掉——删掉一个声称等于改动事实。

### 4. 抽象词代替机制

标题上的生造好认，行文中的靠**复述测试**：读完一句，能否说出"谁、做了什么、结果是什么"？只能复述出一堆抽象词，说明这句的信息被抽象词替代掉了。典型信号是形容词代替机制（`智能的调度`、`优雅的降级`）和名词短语代替动作（`采用乐观并发的协调策略`）。

动作：落回原文或上下文已有的信息。正文其他段、代码、配置里有具体机制就写具体机制；原文本来没有，就把表达压回作者实际声称的范围，或标注缺口。**不能为了"更具体"编造原文没有的机制、数字或步骤。**

### 5. 不必要的术语

术语用对了，但读者不需要这个精度。`这一步做了门控` → 读者要知道的是"检查了什么、不满足怎么办"，"门控"替这两件事占了位置。`结果已落盘` 给存储同事说是压缩，给产品经理说是负担。和第 3 类的区别：第 3 类是词用错了，第 5 类是词没错、场合错。和第 4 类的区别：第 4 类复述不出动作，第 5 类懂行的人能复述，不懂行的人要多转一道弯。

这一类只管把术语当泛称用的情况。词指的就是它的本义操作时（`对文件算哈希`、`校验哈希值`、`开一个事务`、`给这列加索引`）直接用，换成白话反而丢信息。

判据：「术语必要性」那一句问话。

动作：写这个词在这句话里实际指的动作；确实需要术语的，保留并紧跟一句解释。

### 6. 没问过的对立项

句子里多出一个读者没提过的项，作者立起来只为衬托自己要说的那个。形态：`不是 X，而是 Y`、`X，而非 Y`、`重点不在 X，在 Y`、`与其说 X，不如说 Y`、`这不是 X 的问题，是 Y 的问题`；英文 `X, not Y`、`It's not about X. It's about Y.`。同一家族还有主动列举 `我没有改 X`、`X 保持不变`、`这一步不涉及 X`。

读者要先接住 X、理解 X、否定 X，才到 Y；Y 一句话就能说完。

判据（靶子检验）：被否定的 X，读者提过、问过，或读到这里确实会误以为吗？

动作：没有 → 删掉 X，只留 Y 的肯定句。`这次不是重构，只是改了配置项名称` → `这次改了配置项名称`。有 → 保留，这是在纠正一个真实存在的误解；用户问了改动范围时，"没改什么"也照写。

## 目标读者的卡顿是证据

目标读者说"这说的是啥"，就是数据。不能论证读者不该卡，也不能替读者判断负担——改写者不是目标读者。

卡在哪，动作不同：

- 卡在生造词、错位标签、抽象句、对立项 → 改表达。向读者解释这个词"其实是什么意思"不算改。
- 卡在**术语** → 先过术语必要性。不必要的换直白说法；必要的保留，首次出现处补一句解释或链接。删掉必要的术语会让文档失去精确性，代价高于多一句解释。

## 保留规则

- 面向同行的技术文档里，领域通行术语保留，不要求用户证明它通行。`幂等`、`背压`、`p95`、`最终一致性`、`HTTP`、`TTL` 直接放行。其他场景过术语必要性。
- 本文定义过、且一致使用的自造词保留。
- 能预测内容的概括保留，哪怕它抽象。`这个服务读多写少` 是压缩，不是生造。
- 引用原文、命令、接口名、字段名、配置项、报错、代码标识符按字面保留。
- 用户自己用过的词、项目已有的术语表和团队约定优先于本 skill 的默认判断。
- 措辞改动不得改变结论、范围、条件、数字、责任主体。

## 输出规则

默认输出改写结果，不附审稿过程。只在高风险改动处加一行极短说明，例如：`"稳定器"下文无对应物，标签改为正文结论。`

输出形式按载体定：

- **文档是工作区里的文件** → 直接编辑文件。回复里只列改动点：位置、`原文 → 改后`、高风险处一句理由。不把整篇文档贴回对话。
- **短文本贴在对话里**（约 300 字以内）→ 给整段改写版。
- **长文本贴在对话里** → 只给改动的片段，每处 `原文 → 改后`。没列出的部分表示不动。
- **Agent 自己的输出** → 边写边过，直接交付，不附说明，不汇报改了什么。

### 标注模式

用户说"先别改，先标问题""这段哪里看不懂""只做审稿"时启用（对应 shuorenhua 的 annotation mode）。不给整段改写稿，只列最重要的 1–5 个点，每点四个字段：

- `问题类型`：生造词与标签 / 标签错位 / 占用既有词 / 抽象词代替机制 / 不必要的术语 / 没问过的对立项
- `触发点`：命中的词或句子
- `读者会卡在哪`：一句话说明为什么解不出来，或为什么要多转一道弯
- `建议动作`：删掉直写 / 展开缩写 / 合并多名 / 改标签对齐结论 / 换直白说法 / 删掉对立项 / 标注待确认 / 落回已有信息 / 标注缺口 / 补一句解释 / 保持不动

整段没有命中时，不列条目，只输出一行：`未发现生造词、标签错位、占用、抽象替代、不必要的术语或没问过的对立项，建议保持不动。` 不为了凑数硬找。

## 回读检查

提交前逐项过：

1. 每个标签和正文结论对齐。
2. 行文每句能复述出"谁做了什么"。
3. 改动没有引入新的费解词。用一个自己顺手的抽象词或术语替换原来的，等于没改。
4. 事实没动：结论、范围、条件、数字、责任主体逐项可追溯。拿不准的占用是标注了，不是删了。
5. 没有补原文没有的机制、数字、步骤；查不到的地方标了缺口，不是编了一个。
6. 必要的术语和已定义词没有被误杀。读者卡住的必要术语是补了解释，不是删了词。
7. 剩下的每个术语，要么是同行场景不做必要性检验，要么过了必要性：换成直白说法会丢信息。
8. 缩写首次出现处已展开；同一个东西全文只剩一个名字。
9. 剩下的每个 `不是…而是…` 里，被否定的那一项都是读者真会想到的；没有主动列举没人问的"没做什么"。
