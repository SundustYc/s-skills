# 识别信号

> 本文件是解释和示例；行为规则以 `SKILL.md` 为准，两处不一致时按 `SKILL.md`。

生造词列不出词表：每篇文档生造的都不一样，今天删掉的词明天不会再出现。能列的是**形态**。下面每类给识别信号、为什么费解、默认动作、放行条件。中英文同一套形态，英文例子夹在各条里。

形态和 `SKILL.md` 六类问题的对应：1、2、3、7、8 → 生造词与标签；5 → 标签错位；4 → 占用既有词；6 → 抽象词代替机制；9 → 不必要的术语；10 → 没问过的对立项。

## 1. 比喻式命名

**信号**：`X 是 Y 的稳定器 / 压舱石 / 护城河 / 引擎 / 大脑 / 中枢 / 底座`；`把 X 作为 Y 的锚点 / 抓手`；英文 `X is the backbone / cornerstone / brain of Y`。多出现在标题、加粗句和段首。

**为什么费解**：比喻只能表达"重要"或"起作用"，说不出起什么作用。读者要读完正文才能回头猜比喻指的是什么，标签失去了让人决定跳不跳的功能。

**动作**：删掉比喻，把正文结论写成标签。

**放行**：比喻紧跟一句直白解释，且后文再用这个比喻时含义不变。此时它是一个已定义的自造词。

## 2. 抽象名词堆叠

**信号**：两到三个抽象名词连用成一个"东西"：`协调策略`、`韧性恢复流程`、`治理框架`、`演进路径`、`能力矩阵`、`感知层`、`对齐机制`；英文 `Resilience Layer`、`orchestration strategy`、`governance framework`、`capability matrix`。每个词单独看都认识，拼起来不知道指什么操作。

**为什么费解**：它占了一个名词的位置，看起来像是有一个具体的机制，读者去找却找不到。

**动作**：做复述测试。上下文（其他段落、代码、配置）里有具体机制就直接写机制；没有就压回作者实际声称的范围，或标注缺口。

**放行**：这个堆叠是领域通行术语（`一致性哈希`、`服务网格`），或本文已定义。

## 3. 临时组合词

**信号**：文中第一次出现、没有定义、后文不再出现，或每次出现含义都在漂的组合词：`语义锚点`、`上下文对齐层`、`认知闭环`、`意图漂移`、`知识切片`；英文 `semantic anchor`、`context alignment layer`、`intent drift`。

**agent 输出里的变体**：agent 给自己刚做的一步起名字，再拿这个名字当已知概念用：`我加了一层双阶段校验`、`做了 exact-head 检查`、`改成 editorial-row 布局`、`引入了 fallback-aware 的重试`。连字符拼出来的英文复合形容词（`schema-first`、`retry-safe`、`context-aware`）大多属于这类。这些名字只在这一次回复里存在，读者没法查、没法预测。做法只做一次就直接描述：`先查表头再查内容`；确实要反复指代，第一次出现时给定义。

**判据**：搜全文，这个词出现几次？

- 只出现一次，且没有紧跟定义或解释 → 装饰性生造，删掉直写。
- 出现多次，每次指的一样 → 它需要一个定义；在第一次出现处补一句定义。
- 出现多次，每次指的不一样 → 比生造更糟，拆成各自的直白说法。

搜索时连变体一起搜（`语义锚点` 和 `锚点`），别只按精确字串数。

**放行**：第一次出现处给了定义，后文一致使用。只出现一次但紧跟一句直白解释的，按第 1 条比喻式命名的放行条件处理。

## 4. 借术语当形容词（占用）

**信号**：把有固定含义的术语用成模糊的褒义词或程度词：

| 写的 | 实际想说 | 术语本义 |
|---|---|---|
| `原子的` | 快 | 要么全生效、要么全不生效 |
| `幂等` | 有缓存 / 重复调用不会出错 | 同一请求执行多次和一次结果相同 |
| `零拷贝` | 少复制了一次 | 数据不经用户态缓冲区中转 |
| `无状态` | 简单 | 服务不保存请求间的上下文 |
| `正交` | 不相关 / 互不影响 | 两组设计决策可独立变化 |
| `收敛` | 快做完了 | 迭代趋于稳定值 |
| `确定性的` | 可靠 | 相同输入必得相同输出 |

**为什么费解**：懂术语的读者按术语含义理解，理解错；不懂的读者被唬住，以为自己不懂。两种读者都吃亏。

**判据**：把术语的标准定义代入句子，句子还成立吗？

**动作**：换成想表达的直白说法；如果作者本来就是术语本义，保留并确认上下文能支撑。上下文不足以判断是哪一种，保留原词并标注待确认，不默认删——删掉一个声称就是改事实。

## 5. 标签只概括前提

**信号**：标题或加粗句写的是话题、背景、前提，正文的结论是另一件事。`**缓存是系统的稳定器**：……因此需要给热点 key 的 TTL 加随机抖动。` 标签说缓存好，结论是要加抖动。

**为什么费解**：读者按标签分配注意力，跳过这段的人错过了结论，读了的人发现被标签误导。

**判据**：把正文结论压成一句话，和标签对比。

**动作**：改标签，不改正文。

## 6. 形容词替代机制

**信号**：`智能的调度`、`弹性的扩缩容`、`优雅的降级`、`鲁棒的重试`、`动态的路由`、`自适应的限流`；英文 `intelligent scheduling`、`graceful degradation`（无后文说明时）、`leverages an adaptive strategy`。形容词占了机制说明的位置。

**为什么费解**：读者想知道"按什么规则调度""降级降到什么"，得到的只是一个评价。

**动作**：写出机制。查不到就删掉形容词，保留动作本身，必要时标缺口：`调度（规则待补）`。

**放行**：形容词后面紧跟机制说明，形容词只是预告。

## 7. 未展开的缩写

**信号**：全大写或首字母缩写在全文没有一处展开：`DSM 负责下发`、`走 CPL 通道`、`由 OMS 兜底`。

**为什么费解**：缩写是最纯的"必须先解码"。目标读者不认识就完全读不下去，也没法猜。

**判据**：按三问检验第 1 条。领域通行的缩写（`HTTP`、`TTL`、`p95`、`SLO`、`CPU`）直接放行，不要求展开；项目内部、团队内部的缩写按目标读者判——给团队外的人看的文档里，内部缩写一律算未展开。

**动作**：首次出现处展开，后文可以继续用缩写：`下发服务（DSM）负责下发`。展开不出来就标缺口：`DSM（全称待补）`。

**放行**：领域通行缩写；或文档已有缩写表、术语表并覆盖了它。

## 8. 同一概念多个名字

**信号**：全文同一个东西换着叫：`切片 / 分片 / 数据块`，`任务 / job / 作业`，`网关 / 接入层 / 边缘服务`。第 3 条是"一个词多个含义"，这条是反过来的"多个词一个含义"。

**为什么费解**：读者每遇到一个新名字都要停下来判断"这和前面那个是不是同一个"。判错了，后文全错。

**判据**：把这几个名字指的对象写出来，是不是同一个？同一个就是多名。

**动作**：合并成一个名字，用出现最多、或文档 / 代码里已有定义的那个。如果确实是不同的东西，在首次出现处说明区别。

**放行**：代词照应（`它`、`该服务`）不算多名；代码标识符和它的中文说法并列（`ReconcileLoop`，即调和循环）不算多名，那是定义。

和 shuorenhua 的分界：shuorenhua 把"逐次升格换词"当模型腔处理（风格问题）；本 skill 只管"读者能不能确定这是同一个东西"（可读性问题）。同一处两者都命中时各改各的，本 skill 负责统一名字。

## 9. 术语代替白话（不必要的术语）

**信号**：词用对了，读者也可能认识，但这句话换成直白说法一点信息都不丢。多出现在 agent 解释方案、汇报进度、写注释和提交说明的时候：明明是在跟人说"我先检查了一下，不满足就不继续"，写出来是"做了门控"。

**为什么费解**：术语是给需要那个精度的人用的压缩。读者不需要那个精度时，认识这个词的人要多转一道弯（"门控……哦，就是检查"），不认识的人直接卡住。两种读者都没得到好处。

**判据**：换成直白说法，这句话丢信息吗？不丢就换。**写它在这句话里实际指的动作**，不是查表替换——同一个词在不同句子里实际指的事不一样。

**不在此列**：词指的就是它的本义操作。`对请求体算哈希`、`校验哈希值`、`开一个事务`、`给这列加索引`、`走 HTTPS`——这些词没有更直白的等价说法，换掉就丢信息。这一条只管把术语当泛称用：`做了门控` 说的其实是"检查了一下"，`形成闭环` 说的其实是"做完了"。

下表是代表项，不是词表。第二列是它在 agent 输出里通常实际在说的事，改的时候以当前句子为准：

| 写的 | 通常实际在说 | 什么时候确实需要这个词 |
|---|---|---|
| `门控` / `gating` | 先检查某个条件，不满足就不往下走 | 讨论电路、神经网络门控单元、特征开关系统本身 |
| `闭环` | 做完了并确认了结果；或结果会反馈回去影响下一轮 | 控制论、反馈控制系统 |
| `合同` / `契约` / `contract` | 约定、规则、格式要求 | API contract、design by contract 作为正式概念讨论时 |
| `幂等` | 重复执行结果一样，多跑一次没副作用 | 讨论接口设计、重试安全性 |
| `编排` / `orchestration` | 按顺序调用几个步骤；谁先谁后谁等谁 | 讨论 K8s、工作流引擎等编排系统本身 |
| `对齐` | 让两边一致；商量好；核对 | 内存对齐、序列对齐、模型对齐等有本义的场合 |
| `收敛` | 讨论完定下来了；错误不再增加 | 数学、迭代算法 |
| `落盘` | 写到磁盘 / 保存到文件 | 讨论持久化时机、fsync 等细节 |
| `兜底` | 出错时的备用方案；默认值 | 几乎不需要，直接写备用方案是什么 |
| `链路` | 一次请求经过的几个服务；调用路径 | 分布式追踪语境 |
| `语义` | 意思；含义；这个词/字段代表什么 | 编程语言语义、语义版本等有本义的场合 |
| `上下文` / `context` | 前面说过的内容；当时的情况；传给函数的那组参数 | 编程里的 context 对象、LLM context window |
| `拉齐` / `同步一下` | 告诉对方；确认双方信息一致 | 几乎不需要 |
| `原语` / `primitive` | 最基本的操作 | 并发原语、图形原语等正式用法 |
| `范式` / `paradigm` | 做法；套路 | 编程范式作为正式概念讨论时 |

**动作**：写实际动作。确实需要术语（第三列场合，或目标读者是同行且术语是压缩）→ 保留，非同行读者时紧跟一句解释。

**放行**：面向同行的技术文档、API 文档、事故复盘；代码标识符；用户自己先用了这个词；项目术语表里有它。

和 shuorenhua 的分界：`闭环`、`落盘`、`兜底`、`拉齐` 在 shuorenhua 里算商业黑话（风格问题）。本 skill 从"读者要不要多转一道弯"判，重叠处直接改，不转交。

## 10. 没问过的对立项

**信号**：句子结构里有一个被否定的项，而这个项是作者自己引入的：

- `不是 X，而是 Y`、`X，而非 Y`、`并非 X，只是 Y`
- `重点不在 X，在 Y`、`问题不是 X，是 Y`、`与其说 X，不如说 Y`
- 英文 `X, not Y`、`X—not Y`、`It's not about X. It's about Y.`、`This isn't X; it's Y.`
- 同一家族：主动列举没人问的 `我没有改 X`、`X 保持不变`、`这次不涉及 X`、`这里不做 X`

多出现在 agent 解释自己的做法和汇报进度时：`这不是性能问题，而是配置问题`（用户没说过是性能问题）；`我改的是入口函数，没有动数据层`（用户没问数据层）。

**为什么费解**：读者要先接住 X、弄明白 X 是什么、再否定它，才到作者真正要说的 Y。X 是作者为了衬托 Y 立的靶子，读者为一个没人提出的选项付了理解成本。多个这种句子连着出现时，读者会开始怀疑自己是不是漏看了什么。

**判据（靶子检验）**：被否定的 X，读者提过、问过，或读到这里确实会误以为吗？

**动作**：没有 → 删掉 X，只留 Y 的肯定句。

- `这不是性能问题，而是配置里超时设成了 0` → `配置里超时设成了 0`
- `我改的是入口函数，没有动数据层` → `我改了入口函数`
- `The fix isn't in the parser, it's in the tokenizer` → `The fix is in the tokenizer`

**放行**：X 是读者真会想到的。用户先说了"是不是性能问题"，回答 `不是性能问题，是超时设成了 0` 就是在回应用户；用户问"改了哪些地方"，列"没动数据层"是在回答范围。纠正一个文档里已有的说法、或排除一个读者读到这里必然会有的猜测，同样放行。

和 shuorenhua 的分界：shuorenhua 把 `不是…而是…` 当模型腔的一种句式处理（风格问题）。本 skill 从"读者是否为一个没人提出的项付了理解成本"判，重叠处直接改，不转交。

## 快速自查

本 skill 启用时，agent 交稿前跑一遍：

- [ ] 全文搜每个自造词（连变体一起搜）：出现一次且没有定义的删，出现多次的看有没有定义、含义是否一致。
- [ ] 有没有给自己刚做的一步起名字（`双阶段校验`、`exact-head check`、连字符复合词）？直接写做了什么。
- [ ] 每个标题、加粗句、列表项名字：只看它，目标读者能决定跳不跳吗？和正文结论对得上吗？
- [ ] 每个术语：代入标准定义，句子还成立吗？拿不准的标注待确认，不删。
- [ ] 每个术语：换成直白说法丢信息吗？不丢的换掉；留下的，非同行读者能看懂吗？
- [ ] 每个缩写：通行的放行，其余首次出现处展开了吗？
- [ ] 同一个东西全文是不是只有一个名字？
- [ ] 每句：能复述出"谁做了什么，结果是什么"吗？
- [ ] 每个形容词：后面有机制吗？
- [ ] 每个 `不是…而是…` / `X, not Y` / `我没做 X`：被否定的 X 是读者提过或真会想到的吗？不是就删掉 X。
